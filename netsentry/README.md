# NetSentry

**Offline PCAP analysis and basic network anomaly triage in Python.**

NetSentry is an educational defensive-security project for summarizing saved packet captures. It reports protocol counts, top IP endpoints, destination ports, and a small set of transparent triage heuristics.

> **Scope and safety:** NetSentry reads saved `.pcap`/`.pcapng` files only. It does not sniff live interfaces, scan networks, transmit packets, decrypt traffic, or exploit services. Only analyze captures you own or are authorized to handle. Packet captures can contain private or sensitive data; review and sanitize them before sharing.

## Features

- Packet and byte totals
- TCP, UDP, ICMP and DNS visibility
- Top source and destination IP addresses
- Destination-port summary with a small common-port label list
- Low-confidence indicators for repeated endpoint pairs and repeated traffic to ports not in the common-port list
- JSON report output
- Automated tests using a locally generated synthetic capture

## Requirements

- Linux
- Python 3.10+
- Scapy 2.x

## Install

```bash
git clone https://github.com/YOUR-USERNAME/netsentry.git
cd netsentry

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

No root privileges are needed because the program analyzes an existing capture file.

## Usage

```bash
python -m netsentry path/to/capture.pcap
python -m netsentry path/to/capture.pcap --json reports/analysis.json
python -m netsentry path/to/capture.pcap --top 20 --connection-threshold 50
```

If installed as a package:

```bash
python -m pip install .
netsentry path/to/capture.pcap --json reports/analysis.json
```

## Run tests

```bash
python -m unittest discover -s tests -v
```

Tests generate a tiny synthetic capture in a temporary directory; no external network is contacted.

## Suggested learning workflow

1. Start with a synthetic capture generated by the tests.
2. Obtain a benign sample capture from the [Wireshark Sample Captures](https://wiki.wireshark.org/SampleCaptures) collection.
3. Inspect the same file in Wireshark and compare protocol counts and endpoints.
4. Read the JSON report and explain what each indicator does and does not establish.
5. Add a regression test before adding each new heuristic.

## How the heuristics work

- **Repeated endpoint pair:** flags a source/destination pair whose packet count meets `--connection-threshold`. This is a packet-count heuristic, not a count of TCP sessions.
- **Repeated unlisted destination port:** reports ports outside this project's small reference list when at least three packets target them. Legitimate applications frequently use other ports.

These checks are intentionally simple and will produce false positives. They are learning aids, not an intrusion-detection system and not proof that a host is compromised.

## Limitations

- Encrypted payloads are not decrypted or inspected.
- The tool does not reconstruct full TCP sessions or reliably distinguish retransmissions.
- Port labels are incomplete and do not identify the actual application.
- Results depend on capture scope, packet loss, capture duration, and network topology.
- Captures may include sensitive IP addresses, DNS names, or payload metadata. Do not commit private captures or reports containing sensitive information.
